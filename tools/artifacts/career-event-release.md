# 生涯事件、收支与教练联动交付记录

四类主要状态已经接到正式游戏：身体状态、球队地位、场上默契和场外收入。新事件有 11 个场景、22 个选项；轮换、宿敌和恢复各有三段经历，另有拍摄与团队活动。每个选项最多影响两类状态，提示写明金额、分钟变化和持续场次。

选择会进入真实比赛计算。试用增加轮换分钟；医疗安排设置出场上限；负荷与默契影响攻防，负荷也进入伤病概率。临时效果按球队比赛逐场结算，在指定场次后结束。任务反馈来自实际出场、分钟、得分和球队胜负，不能把文案当作已经发生的比赛动作。

模拟收入包括合约工资与场外收入，支出包括恢复支持和团队活动。工资按常规赛球队比赛支付，伤病或禁赛缺阵也照常支付；季后赛不会再次领取常规赛工资。一整季结算精确累计到年薪，重复比赛键不会重复付款或消耗效果。金额是游戏经济规则，并非真实 NBA 球员合同；旧档只记录启用账本后的收入。

球队大当家、已有名单话语权，或默契达到 6/10，可以在赛季中提出一次主教练建议。候选根据球员属性展示球风契合度，管理层采纳后立即切换球队体系，费用由球队承担。五种体系复用已有实现；原有休赛期打法选择保留。本轮把制服组影响落在主教练，没有引入单独的总经理、助教和球探人事系统。

赛前面板展示双方焦点球员、白底照片、自己的球衣立绘、近期表现和本场安排。自建球员立绘与真人照片有明确区别。3D 人物仍需要模型素材，本轮交付照片与立绘展示。

新增逻辑集中在 [生涯事件模块](../../assets/js/perfect-player-career-events.js)，核心通过明确的调用点接入；没有新依赖，也没有保存旧函数后再层层包装的机制。

## 2026-10-03：从现有入口修复状态与存档

用户指出，拆出独立模块还不足以解决反复嵌套和功能失效。此次先处理已复现的问题，修改原有入口与共享状态：

1. `getNextSeasonMods` 保留同一对象引用，旧档缺失伤病风险时迁移旧缓存。普通/重大伤病从这里读取实时风险；续航与退役上下文只计入一次。新赛季不再另外缓存这份风险。
2. `setTeamSystem` 同步现存教练记录，清理阵容缓存并刷新状态条。恢复旧档时以实际球队体系修复不一致的教练记录。
3. 事件查询 `getBranchEventById` 从海报文件移到核心，作为剧情的共同入口。赛季与休赛期进度保存编号，读取正式定义中的 `apply`。回调不写入存档；创建和读档复用同一个清理函数。恢复时先完成待选剧情，再继续比赛，已经执行的选项不会重放。年代序章和已删除的全明星剧情保留兼容规则。
4. 合并两份压缩、写入与元数据更新逻辑。自动和手动保存使用同一队列，恢复等待保存完成；压缩失败仍写原始快照，写入失败有反馈且后续请求可继续。

`tools/test-career-state-continuity.mjs` 覆盖新/旧存档格式、实际风险变化、教练与体系一致性、休赛期页码和队列、动态序章、连点选择、快速保存恢复与写入失败恢复。全部执行检查为 33 个。

## 2026-10-04：暂停赛程与本场打法

根据五条浏览器反馈，移除主菜单的名单核对日期、人物的制作说明和球员卡的估算提示；原始来源与评级标记仍在数据和公开记录中。账本保留收入、支出和合同金额，工资流水在界面合并为一条“年薪／已领工资”，不改变余额或结算规则。季后赛赛前页把收入位置换成本场打法。

常规赛新增暂停、继续和单场推进。暂停允许已经开始的一场完成结算，随后停止；手动逐场推进每次都提供模拟或观看选择。赛前返回赛季会暂停，暂停状态可存读档。复用现有赛季运行归属，旧回调和重复结果不会再推进当前存档。

四种季后赛打法接入正式比赛参数：冲击篮筐提高内线出手和罚球倾向；外线拉开提高三分出手；串联队友减少个人球权并提高助攻权重；均衡执行沿用原有安排。球员相应能力与对手防守决定有上限的球队进攻调整。效果仅对本场对手有效，结算后清除；所选打法与实际赛后回顾进入存档。总决赛使用同一入口。

赛后回顾使用真实的三分命中／出手、罚球、助攻／失误、球队比分和个人得分占比。执行目标达到与比赛获胜分别显示，不声称已经测得某个计划造成胜利的反事实效果。

同样的 40 个随机种子分别运行两种正式引擎、四种打法，共 320 场。下表是每场平均值；属性相同，用于检查选择是否确实进入模拟。

| 指标 | 直接模拟：均衡 → 对应打法 | 观看引擎：均衡 → 对应打法 |
|---|---|---|
| 三分出手：外线拉开 | 7.225 → 9.725 | 6.225 → 8.850 |
| 罚球：冲击篮筐 | 5.850 → 7.150 | 4.750 → 6.150 |
| 助攻：串联队友 | 6.675 → 8.300 | 5.475 → 6.650 |
| 个人出手：串联队友 | 15.825 → 13.625 | 13.025 → 11.775 |

验证同时发现直接模拟结果缺少对手球队标识，个人打法和对位防守读取落空。现已给球队结果补入 `id`，在个人统计入口读取实际对手。测试核对双方箱分与比分守恒、弱项打法的球队进攻代价、效果到期与重复结算。

Chrome 使用独立本地测试角色，完成暂停、存读暂停、直接和观看单场结算、工资汇总、季后赛打法选择和正式结果面板。观看串联打法得到 5 次助攻、0 次失误，球队 107–113 落败，回顾对应实际结果；下一场恢复均衡选择。赛前与赛后在 1440/390/320 宽度下没有横向溢出。季后赛测试使用预置排名进入正式流程，没有人工跑完此前 82 场。

存档验证还复现了两个旧问题：存储层丢弃超过 200KB 的写入却返回成功；系列赛进度只存在于回调闭包里，重开页面会从 G1 开始。已取消本地存储的旧大小限制，让配额错误传到保存提示，并在系列赛对象中保存逐场检查点。实际重开页面后从 G2 继续，赛前所选打法也保留；读档时移除旧结果弹窗，旧比赛回调失效。早期存档没有逐场检查点时，无法恢复其未记录的系列赛局数；已完成系列赛与个人生涯数值继续保留。

## 2026-10-04：让生涯选择的作用可见

用户发现选秀获得教练信任后找不到它的状态和用途。追踪确认：原有 `career.profile` 已经进入 `getCareerProfileEffects`，影响阵容、轮换、攻防、球队去留、续约和市场；新版面板提前返回，旧面板的关系明细因此消失。单次信任变化对分钟的影响很小，也会被整数显示隐藏。

训练营增加关系入口，赛季与赛前在球队地位下直接显示教练信任。生涯关系按球队关系、公众形象、场外机会、生涯声望、本季状态分组；默认展开相关分组，其余可折叠。选项结果显示变化量、当前值和用途，关系页可重新打开。查看关系时暂停常规赛，返回赛前后仍可自行选择模拟或观看。

所有数值复用原始状态与实际计算，没有引入第二套信任值或放大原有加成。轮换倾向显示 `sqrt(minutesFactor) - 1`，对应实际轮换计算；首发竞争显示当前 `lineupBonus`；续约显示 `renewalChanceBonus` 的百分点变化。市场报价和历史评分也读取原有计算。没有真实数值变化的选项不再统一声称会改变人物评价。

验证执行了正式的“中型团队”选秀选择：信任从 0 变为 1，重复点击不重复增加；轮换计划小幅提高，共享比赛防守修正增加，两种完整比赛引擎均读取该修正。续约检查用相同条件下接近原概率边界的随机值，确认真实决策入口读取新增的 0.6 个百分点。结果面板显示 `+1 → 1`，轮换倾向约 +0.1%，首发竞争显示尚无加成。

Chrome 使用独立本地测试角色完成同一真实选秀选择，再预置签约进入正式训练营，重开页面并恢复存档，教练信任仍为 1；进入正式赛前后也能查看。未把预置签约描述为自然游玩完整选秀。桌面、390 和 320 宽度的关系面板已查看，游戏文档无横向溢出。当前共 36 项执行检查全部通过，新增行为放入现有状态连续性检查，未增加依赖或测试框架。
